# TMDb Helper — Enhanced Fork

**Current version:** v7.0.16 &nbsp;|&nbsp; **Base addon:** [plugin.video.themoviedb.helper](https://github.com/jurialmunkey/plugin.video.themoviedb.helper) &nbsp;|&nbsp; **Skin:** Titan Bingie Mod v2.2.3.1 &nbsp;|&nbsp; **Kodi:** 22 (Piers), portable

> A heavily extended fork of TMDb Helper focused on reliable widget refresh, MDBList and Simkl integration, three-way cross-service sync (Trakt ↔ MDBList ↔ Simkl), native Anime and Asian Cinema & TV menus, and Seren-style calendars.

## Install

**From the repository (recommended — Kodi then updates it automatically):**

1. In Kodi: **Settings → File Manager → Add source**, enter `https://minhgi.github.io/tmdbhelper-multiservice/` and give it any name (e.g. "TMDb Helper Multiservice").
2. **Add-ons → Install from zip file** → pick that source → `repository.tmdbhelper-multiservice-1.0.0.zip`.
3. **Install from repository → TMDb Helper Multiservice → Video add-ons → TMDb Helper**.
4. Install the players: **Settings → Players → Install players → Install from URL**, see [Players](#players).

If the source cannot be browsed, use **Install from zip file → Web Location…** with `https://minhgi.github.io/tmdbhelper-multiservice/repository.tmdbhelper-multiservice-1.0.0.zip`.

This fork replaces the stock add-on (same add-on id, `plugin.video.themoviedb.helper`), so remove the original or let it be overwritten. The repository also carries `script.module.jurialmunkey` and `script.module.infotagger`, which the add-on needs and which are not in Kodi's official repository.

**Manual install:** download `repo/zips/plugin.video.themoviedb.helper/plugin.video.themoviedb.helper-<version>.zip` and use **Install from zip file**. Install `script.module.jurialmunkey` and `script.module.infotagger` the same way from `repo/zips/` if they are missing.

**Guides:** [`TMDb_Helper_7.0.16_Install_Instructions.md`](TMDb_Helper_7.0.16_Install_Instructions.md) (full step-by-step install, players, accounts) and [`TMDb_Helper_7.0.16_User_Guide.md`](TMDb_Helper_7.0.16_User_Guide.md) (menus, calendars, players, sync, settings; also as [`.docx`](TMDb_Helper_7.0.16_User_Guide.docx)).

**Repository layout:** the add-on source is in `repo/plugin.video.themoviedb.helper/`; `repo/zips/` is generated by `_repo_generator.py` (run it from the repo root after changing an add-on's `addon.xml` version; it zips each add-on folder and rewrites `addons.xml` and `addons.xml.md5`). The full per-version list of changes is in [`changelog.txt`](repo/plugin.video.themoviedb.helper/changelog.txt); Kodi also shows it on the add-on information screen and under **Tools → Changelog**.

## Features

### Widget Reliability and Speed
- Instant widget refresh after every Trakt / MDBList / Simkl state change (mark watched, rate, scrobble, …)
- Disk-based widget directory cache that survives spurious skin unloads; written in one step, so it is never half-written
- The service rebuilds, in the background, the widget lists you opened in the last 24 hours (not while a video plays), and prefetches the next page of a list you are reading. Setting: **Widgets → Rebuild widgets in the background** (on by default)
- Lists open about twice as fast: the synced Trakt, MDBList and Simkl data is checked once per list instead of once per item (12 test lists: 11.7 s → 6.1 s)
- Hub widget badges update in real time via `Skin.SetString()` — no navigation required
- A list with nothing in it shows a "Nothing here yet" notice instead of silently returning to the menu

### MDBList Service
- **Auth:** OAuth2 device-code flow
- **Watched indicators:** local `MDbListSync.db` unioned with Trakt; delta sync via `/sync/last_activities`
- **Context menu:** mark watched / unwatched, watchlist, collection, rating, drop show, reset resume position, add/remove to list, new list, manage lists
- **Scrobbler:** `POST /scrobble/pause` on pause; `POST /sync/watched` at ≥ 75 % completion
- **Menus:** Watchlist, Liked Lists, User Lists, Recently Watched (Movies / TV Shows / Combined, movies read from the server), In-Progress (Movies / TV shows / Combined), Next Up, Dropped Shows, Account Info (quota)

### Simkl Service
- **Auth:** PIN OAuth2 using `script.simkl`'s published client ID
- **Watched indicators:** local `SimklSync.db` unioned with Trakt and MDBList (anime included)
- **Context menu:** mark watched / unwatched, plan to watch, hold, drop, set as watching, rating
- **Scrobbler:** `POST /scrobble/pause` on pause; `POST /sync/history` at ≥ 75 %; `DELETE /sync/playback/{id}` clears the server resume point
- **Menus:** Plan to Watch, Recently Watched, Watching, On Hold, Dropped, In-Progress (Movies / TV shows / Combined), Next Up, Account Info
- **Cross-device movie resume** read from `GET /sync/playback`

### Trakt Additions
- Dropped shows (hidden from Progress and Next Up), User Lists (browse any Trakt username's public lists), Account Info
- Built-in client id matches the one the Account Manager issues tokens for

### Progress Menus with Anime / Asian Scoping
The Trakt, MDBList and Simkl menus each have:

| Row | Lists |
|-----|-------|
| **All In-Progress …** / **All Next Up** (Trakt: **All Next Episodes**) | Everything, unfiltered |
| **Movies and TV Shows Progress** | The same lists with anime and Asian titles left out |
| **Anime Progress** | The same lists, anime only |
| **Asian Progress** | The same lists, Asian only |

*Anime* = Japanese-language animation. *Asian* follows the Asian Cinema & TV menus: Chinese / Cantonese / Korean / Japanese / Thai language; movies without animation or documentary, TV shows with Drama and without animation, reality or talk.

### Anime and Asian Cinema & TV
- Two hubs in the main menu, each with **Movies** and **TV Shows** submenus and a scoped **Search Movies & TV Shows**
- **Anime:** native (no Otaku needed). Trending and Popular with five periods, Airing Next Season, genres, matched from AniList titles to TMDb (a saved table, filled from the ARM id service and checked against TMDb, remembers each match) so TMDb Helper opens every row
- **Asian:** Chinese, Korean, Japanese, Thai and Taiwanese lists built from TMDb Discover and Trakt (Trending, Most Watched, Top Rated, Genres, By Country), movies and TV

### Calendars
- **TV:** Your Calendar, Premieres, New and All Calendar open a scrollable one-day *show page* (header row per show, episodes under it; Left / Right change the day, also on an empty day). The Asian Drama and Anime TV calendars use the same page. Labels read `1x02. Title (Show)`
- **Movies:** Your Calendar, Your Calendar DVD, All Calendar, All Calendar DVD, the Asian Movies calendars (all five countries and each country) and the Anime Movies calendar open a Seren-style month poster grid (title, date, countdown badge, rating; Left / Right change the month, also on an empty month)
- The Kodi library *Next Aired* calendar is unchanged

### Tools and Settings
- **Tools** menu following Seren's: Sync Tools (clear last sync time, force a sync, rebuild database), Clear Cache tools, Open Settings, Backup / Restore Settings, Changelog
- Every settings category and setting, and every browse-menu row, has a one-line description when highlighted
- Account Info buttons for Trakt, MDBList and Simkl under **Settings → Accounts**

### Cross-Service Sync
- **On-action mirror:** any context-menu action on one service is silently mirrored to all other enabled services
- **Bridge sync:** three-way library reconciliation about 10 seconds after startup and then every *Sync Interval* minutes (default 180; **Settings → Accounts → Cross-service sync**; off until you turn on *Mirror actions across enabled services*; needs Trakt plus MDBList or Simkl) (Seren's snapshot-delta design: shows are never pushed, season 0 is left out, Trakt is refreshed first, pushed-ledger and per-cycle cap)
- Shows a progress notification while it runs (follows the sync-notification setting; not shown during playback)
- **Playback from other add-ons (optional, off by default):** Settings → Accounts → Playback started by other add-ons sends movies and episodes played by add-ons such as Elementum or Seren to MDBList and Simkl (and to Trakt with Include Trakt); a service the playing add-on reports itself is skipped

| Action | Trakt↔MDBList | Trakt↔Simkl | MDBList↔Simkl |
|--------|:---:|:---:|:---:|
| Watched / Unwatched | ✅ | ✅ | ✅ |
| Watchlist | ✅ | ✅ add-only | ✅ add-only |
| Rating | ✅ | — | — |
| Collection | ✅ | — | — |
| Progress (resume) | Trakt→MDBList | Trakt→Simkl | — |

### Other Enhancements
- **Awards DB:** `awards.json` (2.4 MB) migrated to SQLite — O(1) lookups, ~zero RAM
- **Asian drama aliases:** CJK and romanized title variants passed to Seren for better source matching
- **Install players from zip:** Settings → Players → Install players accepts local `.zip` files
- **Parallel ratings fetch:** 6 sequential API calls → parallel `SafeThread` (250 ms–1.5 s → 50–300 ms)
- **Settings backup/restore:** timestamped zip of settings, databases, widget cache and players
- **Package size:** ~3.1 MB savings

## Players

The [`players/`](players) folder holds the player definitions used with this fork: the open-players pack plus players for Seren, Prism, Red Light (Fen Light shape), Otaku Testing and others. `players/tmdbhelper_players.zip` is the same set zipped.

Install from the URL (tested):
1. **TMDb Helper → Settings → Players → Install players → Install from URL** (or **Update players from URL**).
2. Enter `https://raw.githubusercontent.com/minhgi/tmdbhelper-multiservice/main/players/tmdbhelper_players.zip` and confirm.

TMDb Helper remembers the URL, so a later update only needs a confirm. Kodi first asks whether to clear the existing players: **Yes** deletes the player files already in TMDb Helper's players folder, **No** keeps them (files with the same name are overwritten either way).

Or install from a file: download `tmdbhelper_players.zip` from `players/`, then **Install players → Install from zip file** and pick it.

Note for writing your own player files: `tmdb_type` is the correct key for the media type in these players, not `item_type`.

### Foundation (v6.0.12) — Widget Refresh Root Cause Fixes

Nine bugs fixed. Bug 4 was the primary visible cause.

| # | Severity | Bug |
|---|----------|-----|
| 1 | High | `store_last_activity()` ran before `sync_data()` — stamped complete before fetch finished |
| 2 | High | Scrobble completion never triggered `Container.Refresh` or `Widgets.Reload` |
| 3 | High | `timerlock` blocked forced re-sync even when `forced=True` |
| **4** | **Critical** | **Skin reads `widgetreload-movies` but addon only set `TMDbHelper.Widgets.Reload` — cache-bust never fired** |
| 5 | High | `refresh_containers()` override on `ItemRating` was `pass` — silently killed all rating refreshes |
| 6 | High | `ItemUserList.sync()` missing `reset_lastactivities()` — stale timestamps blocked re-fetch |
| 7 | Low | `like_list()` only refreshed on unlike, not like |
| 8 | Medium | `refresh_listing()` early-returned for add operations |
| 9 | Low | Logout didn't clear `LASTACTIVITIES_DATA` or `TraktIsAuth` |

`reload_widgets()` in `kodi_utils.py` sets `TMDbHelper.Widgets.Reload`, `widgetreload`, `widgetreload2`, `widgetreload-movies` and `widgetreload-tvshows` — compatible with Titan / Aura / Arctic-family skins. All refresh paths funnel through this single function.

### API notes (confirmed by live probe)
- **Simkl:** TMDb IDs are accepted by both `/sync/history` and `/sync/add-to-list`. Shows use `POST /sync/add-to-list {"to":"completed"}`. Drop uses `"notinteresting"` with TMDb Helper's login (falls back to `"dropped"`; the two names are matched wherever status is read)
- **MDBList:** use `watchlist/items` and `lists/liked`; the default urllib user agent is rejected (HTTP 403), so a browser-style header is sent. As of 2026-10-13 `GET /sync/watched` does return movies (416 on page 1 on the test account); the earlier "episode-only" finding no longer holds
- **Trakt:** `/sync/playback` is read-only, so progress cannot be written back to Trakt outside a scrobble session

## Known Limitations

| Limitation | Detail |
|-----------|--------|
| **Bridge sync removes** | Additive only. Unwatching on trakt.tv / mdblist.com / simkl.com directly is not propagated by the bridge. Context-menu unwatches ARE mirrored in real time |
| **Progress sync direction** | Trakt → MDBList / Simkl only. MDBList and Simkl **movie** progress is read from the server (cross-device); Simkl **episode** progress is scrobbler-local only |
| **Ratings bridge** | No MDBList GET ratings endpoint. Ratings sync only via the on-action mirror (context menu) |
| **Simkl episode numbering** | The scrobbler and context menu use TMDb episode numbers. For anime where TVDB and TMDb numbering diverge, episode marks may land on the wrong episode. Full TVDB resolution is not implemented |
| **Hub widget static URLs** | Hub slot refresh only works when the slot's path contains a `reload=` token. Fully static paths update on next navigation |
| **Anime / Asian scoping is client-side** | Progress scoping classifies each title from its TMDb details (language, genres), so a title TMDb tags unusually can land in the wrong menu |
| **Trakt Anime calendar** | Limited to titles Trakt tags as anime; the anime movie calendar covers Japanese anime films and ignores the region setting |

## Architecture Notes

**Fix in TMDb Helper, not the skin:** Titan Bingie Mod receives regular skin updates, so changes made to skin files would not survive. TMDb Helper sets the same properties the skin already reads (`widgetreload-movies` etc.).

**Widget cache is disk-based, not memory:** each widget request spawns a separate `plugin.py` process. Window properties are used for cross-process invalidation (`LastInvalidated`); the filesystem is the cross-process data store.

**MDBList local DB is sparse:** `MDbListSync.db` contains rows for items the user has interacted with in Kodi plus what the sync fetched; the bridge reads MDBList's live state from the API for the complete picture.

**Direct DB writes for toggles:** after each API POST the toggle state is written directly to the local sync database so context-menu labels reflect the new state immediately.

**`reset_lastactivities()` intentionally omitted for MDBList watched:** calling it triggers `MDbListSyncWatched.sync()` on the next `Container.Refresh`, which calls `clear_columns()` and wipes the `plays=1` that was just written.

**Cross-sync loop safety:** mirror functions in `cross_sync.py` call API endpoints directly and never instantiate `Item*` sync classes — instantiating `ItemMDbListWatched.sync()` from inside a Trakt sync would call `mirror_watched_to_trakt()` again and echo forever.

**Hub widget refresh via `Skin.SetString()`:** hub containers source their content from `$INFO[Skin.String(key.path)]`. When `Skin.SetString()` updates the value, Kodi's info manager marks the dependency stale and `CDirectoryProvider` re-fetches. The `reload=` token baked into the path is what makes this possible.

**Calendar windows:** the movie month grid (`window/moviecalendar.py`) and the TV show page (`window/showcalendar.py`) are `WindowXMLDialog`s opened from the `dir_calendar_window` / `dir_calendar_shows_window` routes. Callback exceptions inside a `WindowXMLDialog` are swallowed by Kodi, so cleanup lives in `try/finally`. In plugin URLs a literal comma is split by Kodi's parameter parser; encode it as `%2C`.
